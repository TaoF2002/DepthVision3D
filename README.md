# DepthVision3D

DepthVision3D 是一个运行在 iPhone 端的 2D → 3D 实验项目。它使用 **Depth Anything V2 Small（Core ML）** 估计相对深度，再通过 **Metal** 生成左右眼并排（Side-by-Side，SBS）内容，并可在手机端预览或输出到 View1 眼镜外屏。

> 深度推理和 SBS 合成都在 iPhone 上完成，眼镜端当前负责显示结果，并不在眼镜上运行模型。

## 主要功能

### 图片转换

- 从系统图册选择图片，或使用 App 内置示例。
- 将 HEIF、HDR、Display-P3 等图片统一转换为标准动态范围的 8-bit 图像，减少解码和 Metal 纹理加载失败。
- 使用 Depth Anything V2 生成相对深度结果。
- 使用 Metal 生成左右眼 SBS 立体图。
- 将左右眼内容等比例放入各自的 1920×1080 区域，最终生成固定 3840×1080 Full-SBS 图片；比例不一致时自动添加黑边，避免拉伸。
- 提供柔和 3D、标准 3D、沉浸 3D 三种预设，通过下拉菜单一键设置立体强度、聚焦平面、最大视差和深度曲线；四项参数也可继续手动微调。
- 支持预览、分享，并将结果同步显示到已连接的 View1。
- 转换完成后显示引擎准备、图片归一化、V2 推理、Metal SBS、输出布局和总耗时。

### 视频转换

- 支持从系统图册选择视频，图册选择器只显示视频。
- 保留文件导入入口，便于 V2/V3 使用完全相同的测试文件进行对比。
- 逐帧生成 SBS 视频，每 3 帧更新一次深度，并进行时序平滑。
- 读取视频方向信息并纠正横竖屏方向，将每眼画面等比例放入 1920×1080 区域，固定输出 3840×1080 Full-SBS H.264 MP4。
- 横屏、竖屏、方形和超宽视频会根据原始宽高比自动添加黑边，不通过拉伸填满屏幕。
- 视频处理阶段先生成无声 H.264 SBS MP4，再在第二阶段封装原视频音轨，避免音频和逐帧推理互相阻塞。
- 支持手机与 View1 共用同一个 `AVPlayer` 播放转换结果。
- 支持取消正在进行的图册读取、逐帧转换或音频封装，并清理未完成的临时文件。
- 转换完成后显示取帧/解码等待、方向缩放、V2、Metal、3840×1080 布局、编码、音频封装、总耗时和实际处理帧率。

### View1 外屏输出

- 识别 1920×1080 和 3840×1080、60 Hz 的外接屏幕模式。
- 无法自动识别时，可在手机端点击“确认为 View1”。
- 支持显示 SBS 图片和播放 SBS 视频。
- View1 断开并重新连接后，可恢复最近请求的图片或视频内容。
- 视频声音由 iOS 音频路由决定，可能从 iPhone、蓝牙设备或其他系统选择的输出设备播放。

## 处理流程

### 图片

```text
图册图片 / 内置示例
        ↓
标准动态范围与尺寸归一化
        ↓
等比例放入 518×392 模型输入并裁除深度 padding
        ↓
Depth Anything V2 相对深度推理
        ↓
Metal 左右眼视差合成
        ↓
每眼等比例放入 1920×1080，空余区域填黑
        ↓
手机预览 / 分享 / View1 SBS 输出
```

### 视频

```text
图册视频 / 文件视频
        ↓
AVAssetReader 逐帧读取并应用视频方向信息
        ↓
V2 深度推理 + 时序平滑
        ↓
Metal SBS 合成
        ↓
等比例放入 3840×1080 Full-SBS 画布并写入 H.264
        ↓
封装原视频音轨
        ↓
手机与 View1 共用 AVPlayer 播放
```

## 输出尺寸与比例

当前实现按照 View1 3D 模式为 **3840×1080 Full-SBS** 的方案输出，左右眼各占一个 **1920×1080** 区域。素材始终采用 Aspect Fit，未占满的区域写入黑色像素，因此播放器或外接设备无需再次通过拉伸修正比例。

| 原始比例 | 每眼内容尺寸（约） | 自动黑边 |
| --- | ---: | --- |
| 16:9 | 1920×1080 | 无 |
| 4:3 | 1440×1080 | 左右各 240 px |
| 1:1 | 1080×1080 | 左右各 420 px |
| 9:16 | 608×1080 | 左右各约 656 px |
| 21:9 | 1920×823 | 上下各约 128 px |

> 3840×1080 Full-SBS、左右眼顺序和 View1 3D 模式切换方式仍需以公司设备规范及真实 View1 测试结果为准。

## 参数说明

- **立体强度**：控制左右眼画面的最大水平视差。数值越大，立体感越明显，但过大可能造成重影、边缘拉伸或观看不适。
- **聚焦平面**：决定深度值处于哪个位置时左右眼画面不发生位移。它会改变哪些内容看起来位于屏幕前方或后方。
- **最大视差**：限制左右眼总位移占单眼内容宽度的比例，防止极端深度产生过大的视差。
- **深度曲线**：调整中间深度层次。大于 1 时压低中间层次、效果更柔和；小于 1 时强化中间层次、效果更沉浸，同时保持聚焦平面和深度两端不变。

| 3D 模式 | 立体强度 | 聚焦平面 | 最大视差 | 深度曲线 |
| --- | ---: | ---: | ---: | ---: |
| 柔和 3D | 1.5% | 0.50 | 1.5% | 1.20 |
| 标准 3D | 2.5% | 0.50 | 2.5% | 1.00 |
| 沉浸 3D | 4.0% | 0.50 | 3.5% | 0.80 |

选择预设后仍可使用滑块微调任意参数；手动调整后模式显示为“自定义”，再次选择预设可恢复该模式的默认值。

## 性能统计

图片或视频转换完成后，App 会在页面底部显示本次性能报告，并将相同内容输出到 Xcode 控制台。报告文本支持选择和复制，可用于比较模拟器、不同 iPhone、不同分辨率和不同帧率素材。

- 图片分别统计引擎准备、标准化、V2 深度推理、Metal SBS、深度预览与固定画布布局。
- 视频分别统计引擎初始化、素材信息读取、管线准备、取帧/解码等待、方向修正与缩放、V2 推理、Metal SBS、固定画布布局、编码等待与写入、编码收尾及音频封装。
- “编码等待与写入”表示转换线程等待编码器接收帧及提交帧的时间；硬件编码可能与其他阶段并行，因此它不等于编码芯片的全部工作时间。
- 总耗时还包含任务调度、缓冲区创建、进度回调及其他少量未单列开销，各子项不要求与总耗时严格相加相等。

## 环境要求

- iOS 17.0 或更高版本。
- 支持 Metal 的 iPhone 或 iOS 模拟器。
- 建议使用当前版本 Xcode 打开 `DepthVision3D.xcodeproj`。
- 测试 View1 输出需要真实 iPhone、View1 眼镜及对应的外接显示连接方式。

项目已包含编译后的 `DepthAnythingV2SmallF16.mlmodelc`，正常运行不需要下载模型或安装额外的 Swift Package。

## 运行方法

1. 克隆仓库：

   ```bash
   git clone https://github.com/TaoF2002/DepthVision3D.git
   ```

2. 使用 Xcode 打开 `DepthVision3D.xcodeproj`。
3. 在项目的 Signing & Capabilities 中选择自己的开发团队，并按需修改 Bundle Identifier。
4. 选择 iPhone 或模拟器后运行。
5. 图片测试：选择“图片”，导入图片后点击“生成立体图”。
6. 视频测试：选择“视频”，从图册或文件导入视频并等待转换完成。

模拟器会使用 CPU 执行 Core ML 推理，速度可能较慢；iPhone 真机会使用系统可用的 CPU、GPU 或 Neural Engine。

## View1 测试建议

1. 先在 iPhone 上启动 App，再连接 View1。
2. 等待“View1 眼镜输出”区域显示已连接；若外屏显示为未知设备，可点击“确认为 View1”。
3. 转换一张图片，检查左右眼顺序、立体强度、聚焦平面和画面边缘。
4. 转换一个带声音的短视频，检查手机预览、View1 画面、播放同步和声音路由。
5. 断开并重新连接 View1，检查最近内容能否恢复。

与 V3 方案对比时，建议双方使用同一个文件导入视频，并统一输入素材、SBS 左右眼顺序、输出分辨率、立体强度及聚焦平面。

## 当前实现与限制

- Depth Anything V2 输出的是归一化后的相对深度，不是以米为单位的真实深度。
- 输出属于基于深度视差生成的 2.5D SBS 内容，不是包含物体背面几何信息的完整 3D 模型。
- `DepthRelief` 当前复用 V2 和 Metal 管线，并使用更强的视差参数；它不是已经确认的专有 Depth Relief 算法。
- 图片进入立体合成前最长边限制为 1920 像素；图片和视频的最终 SBS 结果固定为 3840×1080，每眼画布为 1920×1080。
- 竖屏素材虽然不会再被拉伸，但在固定 518×392 的横屏深度模型输入中占用的有效宽度较少，细小物体的深度精度可能低于横屏素材。
- 视频当前使用 H.264 编码，平均码率约 16.6 Mbps；高帧率或高运动场景仍需在真实设备上验证压缩画质。
- 视频每 3 帧更新一次深度，性能更好，但快速运动场景可能出现深度变化滞后或闪烁。
- 常见 AAC 音轨可以直接封装进 MP4；部分 MOV/PCM 或特殊音频格式可能需要额外转码。
- HEIF、HDR 和 Display-P3 图片会转换为标准动态范围 8-bit 图像以保证 Core ML 与 Metal 兼容，因此不会保留完整 HDR 和广色域信息。
- 当前 View1 连接代码仍使用部分已被新 iOS SDK 标记为弃用的 `UIScreen` 外屏 API。它们目前仍可编译运行，但最终兼容性需要在真实 View1 设备上验证。

## 后续优化方向

- 根据 View1 真机观看结果继续校准三种 3D 预设，并评估视频稳定性和输出画质档位。
- 保留 V2 作为稳定基线，评估将 Depth Anything V3 Small Core ML 作为可切换实验引擎；接入前需确认模型输入输出、深度方向、最低系统版本、ANE 兼容性、性能和许可证。
- 增加快速预览与最终 View1 输出两种处理档位，避免参数调试阶段反复生成完整 3840×1080 视频。
- 评估在视频解码阶段直接缩放到目标内容尺寸、合并 Core Image/Metal 中间处理、缓存深度纹理，以及根据运动程度动态调整深度推理间隔。
- 使用真实 iPhone 记录不同长度和帧率视频的转换时间、峰值内存、温度与文件大小，再决定分辨率、码率和推理频率的默认值。

## 核心文件

- [`DepthEstimator.swift`](DepthVision3D/DepthEstimator.swift)：加载 Core ML 模型，通过等比例输入和深度 padding 裁剪生成相对深度。
- [`StereoRenderer.swift`](DepthVision3D/StereoRenderer.swift)：使用 Metal 生成左右眼 SBS 图片或视频帧。
- [`ProcessingService.swift`](DepthVision3D/ProcessingService.swift)：图片归一化、深度推理、立体合成及 View1 固定画布布局。
- [`VideoConverter.swift`](DepthVision3D/VideoConverter.swift)：视频方向修正、读帧、推理、固定画布写入、取消和音轨封装。
- [`AppViewModel.swift`](DepthVision3D/AppViewModel.swift)：手机端任务状态、性能报告和图片、视频处理入口。
- [`CinemaSession.swift`](DepthVision3D/ios_View1Cinema_View1Cinema_Playback_CinemaSession.swift)：手机与 View1 共用的播放及展示状态。
- [`ExternalDisplayManager.swift`](DepthVision3D/ios_View1Cinema_View1Cinema_ExternalDisplay_ExternalDisplayManager.swift)：外接屏幕检测、确认、连接和重连。
- [`ExternalRootView.swift`](DepthVision3D/ios_View1Cinema_View1Cinema_ExternalDisplay_ExternalRootView.swift)：View1 外屏显示界面。
- [`DepthProcessor.swift`](DepthVision3D/DepthProcessor.swift)：View1 接口与现有 V2 管线之间的兼容层。
